# Corum v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extract the existing AcademicsWiki framework into an installable, content-free Corum repository with deterministic Canvas capture, optional direct Jira application, and LLM-owned wiki generation.

**Architecture:** Corum is an installed Python package that operates on an explicit private vault. Python captures Canvas data, validates state, applies exact Jira plans, and reports results; copied and refactored skills own scoping, approval, wiki authorship, and orchestration.

**Tech Stack:** Python 3.12, `httpx`, Pydantic 2, PyYAML, Beautiful Soup, markdownify, pytest, pytest-asyncio, jsonschema, Markdown.

**Spec:** `docs/superpowers/specs/2026-09-06-corum-framework-design.md`

## Global Constraints

- Do not modify `/home/daniel/Documents/AcademicsWiki` or `/home/daniel/Documents/AcademicsWikiFramework`; they are read-only extraction sources.

- Do not put wiki planning or authorship in Python.
- Jira is enabled by default but may be disabled globally or per course.
- Wiki generation is enabled by default but may be disabled globally or per course.
- Secrets come only from `CORUM_CANVAS_TOKEN`, `CORUM_JIRA_EMAIL`, and `CORUM_JIRA_API_TOKEN`.
- Create no empty modules: every new file must be exercised by a test or an installed command.
- Reuse current code and skills where they fit; refactor only old-layout, MCP, and mandatory-feature coupling.

Use Pydantic models with these required shapes:

```python
class FeatureSwitch(BaseModel):
    enabled: bool = True

class Features(BaseModel):
    jira: bool = True
    wiki: bool = True

class WorkspaceDetails(BaseModel):
    timezone: str
    term: str

class CanvasWorkspace(BaseModel):
    host: HttpUrl

class WorkspaceFeatures(BaseModel):
    jira: FeatureSwitch = Field(default_factory=FeatureSwitch)
    wiki: FeatureSwitch = Field(default_factory=FeatureSwitch)

class JiraWorkspace(BaseModel):
    site: HttpUrl
    project: str
    transitions: dict[str, str] = Field(default_factory=dict)

class CalendarFiles(BaseModel):
    timetable: Path
    term: Path

class WorkspaceConfig(BaseModel):
    schema: Literal[1]
    workspace: WorkspaceDetails
    canvas: CanvasWorkspace
    features: WorkspaceFeatures = Field(default_factory=WorkspaceFeatures)
    jira: JiraWorkspace | None = None
    calendar: CalendarFiles

class CanvasCourse(BaseModel):
    id: int = Field(gt=0)
    sources: list[Literal["announcements", "assignments", "files", "pages", "modules", "syllabus"]]
    folders: dict[str, str] = Field(default_factory=dict)

class CourseFeatures(BaseModel):
    jira: FeatureSwitch | None = None
    wiki: FeatureSwitch | None = None

class JiraCourse(BaseModel):
    epic: str

class WikiCourse(BaseModel):
    split_rules: str = "default"

class CourseConfig(BaseModel):
    schema: Literal[1]
    code: str
    canvas: CanvasCourse
    features: CourseFeatures | None = None
    jira: JiraCourse | None = None
    wiki: WikiCourse | None = None
```

`corum init PATH` creates `corum.yaml` and `courses/`, and refuses any non-empty target. Agent files are added when the agent kit exists in Task 5. `corum doctor PATH` loads every `courses/*/course.yaml`, resolves features, and exits nonzero on validation failure. Do not test network connectivity.
