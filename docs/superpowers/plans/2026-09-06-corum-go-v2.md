# Corum Go v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Corum's Python package with one clean Go v2 binary that preserves the local-first Canvas/Jira workflow, ships through GoReleaser, self-updates once daily when invoked, and overwrites the embedded agent toolkit in every registered vault.

**Architecture:** Build one `CGO_ENABLED=0` executable with focused internal packages and root-level embedded assets. Productionize the already-proven official Go MCP OAuth sequence first, then add clean v2 vaults, Jira safety behavior, Canvas capture, and the Odyssey-derived installer/release/update path before deleting Python in one final cutover.

**Tech Stack:** Go 1.26, standard library, official MCP Go SDK v1.7, Huh v2, YAML v3, html-to-markdown v2, pure-Go PDF extraction, minio/selfupdate, GoReleaser v2, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-06-corum-go-v2-design.md`

## Global Constraints

- Release only one Go binary named `corum`; do not ship Python or a runtime bridge.
- Support `linux/amd64`, `linux/arm64`, `darwin/amd64`, and `darwin/arm64` with `CGO_ENABLED=0`.
- Use a clean `version: 2` format. Reject v1 without modifying it; do not implement migration.
- A workspace/course service is enabled by the presence of its configuration block; do not restore a separate `features` mapping.
- Jira authentication is OAuth-only through `https://mcp.atlassian.com/v2/mcp`; never add API-token fallback, Rovo CLI coupling, or keyring storage.
- Authenticate at the canonical Rovo URL, then reuse the token source at `?tools=all`; never authenticate directly through the query-bearing URL.
- Preserve exact-plan approval, sequential Jira writes, ownership checks, write-state classification, partial-write blocking, and read-only reconciliation.
- Wiki content remains LLM-authored. Go may copy toolkit files and validate state, but must not synthesize or finalize wiki prose.
- Corum owns and overwrites only `AGENTS.md`, `skills/`, `templates/`, and `.corum/toolkit-version` inside a vault.
- Never overwrite `corum.yaml`, `courses/`, wiki pages, run state, Canvas state, Jira state, or OAuth data during toolkit updates.
- Automatic update checking runs at most once per 24 hours and only during a Corum invocation. `DISABLE_AUTO_UPDATES=1` skips it; `corum update` bypasses it.
- Automatic update failure must not fail the requested command. Explicit `corum update` failure must return nonzero.
- Do not add sandboxing, containers, a server, database, scheduler, daemon, multi-user hosting, or background process.
- Use `/home/daniel/Projects/odyssey-cicd` as the reference for installer, archive verification, self-update, semantic tags, and GoReleaser workflow shape.
- Run focused package tests during Tasks 1–6. Defer `go test ./...`, race, vet, release snapshot, installer smoke, and installed-binary acceptance to Task 7.
